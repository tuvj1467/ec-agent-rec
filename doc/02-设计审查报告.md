## 三、关键设计问题

### 问题1：Qdrant 距离度量与 LightGCN 打分不一致 ⚠️严重

**问题描述**：
- LightGCN 模型使用**内积（Dot Product）**计算用户-商品分数：`score = user_emb · item_emb`
- 但 Qdrant 默认配置使用 **Cosine 距离**（见 [config.py:69](file:///d:/ec-agent-rec/config/config.py)）
- Cosine 距离会对向量做 L2 归一化，导致 `cosine(u, i) = dot(u, i) / (|u| * |i|)`，与原始内积打分不一致

**影响**：
- 召回结果排序与模型训练目标不匹配
- 模型学到的向量模长信息被丢弃
- 推荐效果可能下降

**改进方案**：
```python
# 方案A：使用 Dot 距离（推荐）
QDRANT_CONFIG = {
    'distance': 'Dot',  # 与 LightGCN 内积打分一致
}

# 方案B：保持 Cosine，但训练时对向量归一化
# 在 LightGCN.forward 中添加归一化
```

### 问题3：Agent 推荐未过滤已购商品 ⚠️中等

**问题描述**：
- 评估器 [evaluator.py:55](file:///d:/ec-agent-rec/model/evaluator.py) 正确地排除了训练集商品
- 但 Agent 推荐 [recommendation_engine.py:80](file:///d:/ec-agent-rec/agent/recommendation_engine.py) 没有过滤用户已购商品
- 会导致推荐用户已经买过的商品

**影响**：
- 用户体验差
- 推荐结果不实用

**改进方案**：
```python
def recommend(self, user_id, top_k=None, use_cache=True, exclude_items=None):
    # ...
    results = self.vector_retriever.retrieve(user_embedding, top_k=top_k * 2)
    
    # 过滤已购商品
    if exclude_items:
        results = [r for r in results if r['original_item_id'] not in exclude_items]
    
    return results[:top_k]
```

### 问题4：缓存失效策略粗糙 ⚠️轻微

**问题描述**：
- [recall_cache.py](file:///d:/ec-agent-rec/cache/recall_cache.py) 使用固定 TTL=3600秒
- 用户产生新的购买行为时，缓存不会主动失效
- 会导致新用户行为无法立即反映在推荐中

**改进方案**：
```python
# 用户产生购买行为时主动失效缓存
def on_user_buy(self, user_id):
    self.recall_cache.invalidate(user_id)
    
# 或采用更精细的失效策略：
# 1. 活跃用户短 TTL（5分钟）
# 2. 不活跃用户长 TTL（1小时）
```

### 问题7：负采样策略未优化 ⚠️轻微

**问题描述**：
- [dataset.py:50](file:///d:/ec-agent-rec/data_processing/dataset.py) 使用均匀负采样
- 未考虑商品流行度，热门商品容易被采为负样本，造成假负样本

**改进方案**：
```python
# 流行度加权负采样
def popularity_based_negative_sampling(item_popularity, num_negatives):
    prob = item_popularity ** 0.75  # 平滑
    prob = prob / prob.sum()
    return np.random.choice(len(prob), size=num_negatives, p=prob, replace=False)
```

## 五、面试应对策略

### 5.1 主动提及的设计权衡
- "我注意到 Cosine 和 Dot 的差异，最终选择 Dot 保持与 LightGCN 一致"
- "user_embedding 当前从内存加载，生产环境会迁到 Redis"
- "缓存采用 TTL + 主动失效双策略"

### 5.2 被问到时的回答思路
- **"为什么用 LightGCN？"** → 对比 NeuMF/GraphSAGE，强调 LightGCN 去掉了特征变换和非线性激活，在推荐场景下效果更好且训练快
- **"为什么用 Qdrant？"** → 对比 FAISS/Milvus，Qdrant 支持负载过滤、云原生、API 友好
- **"如何解决冷启动？"** → 当前方案局限，可补充：基于规则的热门推荐 + 基于内容的召回

项目整体设计**合理且可演示**，作为简历项目能完整展示推荐系统 + Agent 开发能力。建议在面试前修复**距离度量**和**已购过滤**两个关键问题，并准备好被追问时的设计权衡解释。
