# 电商推荐 Agent 项目规划

## 一、项目概述

基于阿里云天池 UserBehavior 数据集，构建一个以 LightGCN 图推荐模型为核心、Qdrant 向量数据库为召回引擎、LLM 为导购交互层的电商推荐 Agent 系统。

### 1.1 项目定位
- 简历项目，展示完整的推荐系统 + Agent 开发能力
- 技术栈覆盖：数据工程、图神经网络、向量检索、大模型应用
- 模块化设计，可独立运行各模块

### 1.2 核心价值
1. 基于图神经网络的精准推荐
2. 向量数据库实现高效召回
3. LLM 驱动的自然语言导购交互
4. 缓存优化提升系统性能

---

## 二、技术架构

### 2.1 整体架构图

```
天池 UserBehavior 数据集
         ↓
[数据层] 离线清洗、构造交互图
         ↓
[模型层] LightGCN 图推荐模型训练
         ↓
[向量层] 输出 user_embedding、item_embedding
         ↓
[召回层] Qdrant 向量库（物品向量索引）
         ↓
[缓存层] Redis 缓存高频召回结果
         ↓
[Agent层] LLM 电商导购对话
         ↓
[输出层] 推荐商品 item_id 列表 + 导购回复
```

### 2.2 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 数据处理 | pandas, numpy | 数据清洗、特征工程 |
| 图构造 | scipy, networkx | 稀疏矩阵、图结构 |
| 推荐模型 | PyTorch + LightGCN | 图卷积神经网络推荐 |
| 向量数据库 | Qdrant | 稠密向量检索 |
| 缓存 | Redis | 高频召回结果缓存 |
| Agent 框架 | LangChain / 原生实现 | LLM 对话编排 |
| LLM | OpenAI / 本地模型 | 导购对话生成 |

## 三、模块设计

### 3.1 数据处理模块 (`data_processing/`)

**职责**：原始数据清洗、用户-商品交互图构造

**核心文件**：
- `data_cleaner.py` - 数据清洗器（去重、过滤异常值、时间范围过滤）
- `graph_builder.py` - 图构造器（构造用户-商品二部图、邻接矩阵）
- `dataset.py` - 数据集封装（训练/验证/测试集划分）

**输入**：天池 UserBehavior.csv（user_id, item_id, category_id, behavior_type, timestamp）
**输出**：
- 清洗后的交互数据
- 用户-商品邻接矩阵（稀疏矩阵）
- 训练/验证/测试集

### 3.2 模型训练模块 (`model/`)

**职责**：LightGCN 模型定义、训练、评估、向量导出

**核心文件**：
- `lightgcn.py` - LightGCN 模型定义
- `trainer.py` - 训练器（训练循环、损失计算、优化器）
- `evaluator.py` - 评估器（Recall@K, NDCG@K, Precision@K）
- `embedding_exporter.py` - 向量导出器

**输入**：用户-商品交互图
**输出**：
- user_embedding.npy - 用户向量
- item_embedding.npy - 商品向量
- 模型检查点
- 训练日志

### 3.3 向量入库模块 (`vector_store/`)

**职责**：商品向量入库 Qdrant、向量检索

**核心文件**：
- `qdrant_client.py` - Qdrant 客户端封装
- `indexer.py` - 向量索引器（批量入库、索引管理）
- `retriever.py` - 检索器（向量相似度检索）

**输入**：item_embedding.npy
**输出**：
- Qdrant 集合（collection）
- 向量检索结果

### 3.4 缓存模块 (`cache/`)

**职责**：Redis 缓存高频召回结果，减轻向量库压力

**核心文件**：
- `redis_client.py` - Redis 客户端封装
- `recall_cache.py` - 召回缓存管理器

**缓存策略**：
- 热门用户召回结果缓存
- LRU 淘汰策略
- TTL 过期机制

### 3.5 Agent 模块 (`agent/`)

**职责**：电商导购对话、推荐结果生成

**核心文件**：
- `ecommerce_agent.py` - 电商 Agent 主类
- `prompt_templates.py` - Prompt 模板
- `recommendation_engine.py` - 推荐引擎（向量召回 + 排序）
- `response_generator.py` - 回复生成器

**工作流程**：
1. 获取 user_id
2. 拉取 user_embedding
3. Qdrant 向量检索召回相似商品候选集
4.（可选）Redis 缓存命中检查
5. LLM 结合候选商品，生成导购回复
6. 输出 item_id 列表 + 自然语言回复

### 3.6 配置与入口

**核心文件**：
- `config.py` - 全局配置
- `main.py` - 主入口（训练 / 入库 / 对话 模式）
- `requirements.txt` - 依赖列表

## 四、数据流程详解

### 4.1 离线流程（训练 + 入库）

```
1. 数据清洗
   输入: UserBehavior.csv (~1亿条)
   操作: 去重、过滤异常时间戳、行为类型过滤
   输出: clean_interactions.csv

2. 图构造
   输入: clean_interactions.csv
   操作: 构建用户-商品二部图、生成邻接矩阵
   输出: adj_matrix.npz, user_mapping.json, item_mapping.json

3. 模型训练
   输入: 邻接矩阵、交互数据
   操作: LightGCN 训练（BPR损失）
   输出: user_embedding.npy, item_embedding.npy, model.pt

4. 向量入库
   输入: item_embedding.npy, item_mapping.json
   操作: 批量写入 Qdrant
   输出: Qdrant collection 就绪
```

### 4.2 在线流程（Agent 对话）

```
用户输入: "帮我推荐一些商品" + user_id
           ↓
1. 获取用户向量
   从 user_embedding.npy 中读取
           ↓
2. 缓存检查
   查询 Redis: user_id:{user_id}:recall
   命中 → 直接返回缓存结果
   未命中 → 继续下一步
           ↓
3. 向量检索
   Qdrant 搜索: 用 user_embedding 检索 item_embedding
   返回 Top-K 相似商品
           ↓
4. 缓存写入
   将召回结果写入 Redis（设置 TTL）
           ↓
5. LLM 生成回复
   输入: 用户问题 + 候选商品列表
   输出: 导购回复 + item_id 列表
           ↓
最终输出: 自然语言导购回复 + 推荐商品ID列表
```

## 八、注意事项

1. **数据规模**：天池数据约 1 亿条，需考虑内存优化（采样、稀疏矩阵）
2. **模型训练**：LightGCN 对 GPU 有要求，需支持 CPU fallback
3. **向量库**：Qdrant 需 Docker 运行，或使用本地模式
4. **LLM**：使用 Mock LLM 模式支持无 API Key 情况下的演示
5. **命名规范**：严格遵循 snake_case 命名规范
